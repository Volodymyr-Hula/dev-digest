## Codebase Patterns
<!-- unwritten conventions and architectural decisions, with the reason -->
- **Change the web port in `client/package.json` (`next dev -p` / `next start -p`), not in `client/.env`** — no client code reads `WEB_PORT`; `client/.env` keeps it only to mirror `server/.env`, where it sets the API's CORS origin. Keep all three equal. Evidence: `client/package.json:7`; `grep -rn WEB_PORT client` hits only `.env*` and CLAUDE.md. (2026-11-19)
- **Run `./scripts/e2e.sh` locally after a `reviewer-core`-only change** — `.github/workflows/e2e-web.yml` `paths:` (`:14-24`) omit `reviewer-core/**`, yet the API imports reviewer-core source at runtime (comment at `:73-81`), so CI never runs e2e for such a change. Alternatively, add the filter (root `CLAUDE.md` Gotchas: CI path filters). Evidence: `.github/workflows/e2e-web.yml:14-24`. (2026-11-20)
- **After changing a default in `server/.env.example` or `client/.env.example`, update existing `.env` files by hand** — `dev.sh` copies the example only when `.env` is missing, and `.env` beats the code defaults, so a stale `DATABASE_URL=…:5432` kept pointing at another project's Postgres after the move to 55432. Evidence: `scripts/dev.sh:42`. (2026-11-19)

## Tool & Library Notes
<!-- dependency quirks, version-specific behaviour, CLI gotchas -->
- **Restart the developer's `pnpm dev` (client) after running `./scripts/e2e.sh`** — e2e starts a second `next dev` in the same `client/` folder with `NEXT_PUBLIC_API_BASE=http://localhost:3101` (`scripts/e2e.sh:42,148`), and both share `client/.next`, so afterwards the dev web app on :13000 calls the e2e API (`Connecting to 'http://localhost:3101/repos' violates the following Content Security Policy directive`) and returned 404 for an existing `/skills/[id]` page. Evidence: browser console on :13000 right after an e2e run. (2026-11-24)
- **If `agent-browser` fails with `mise ERROR agent-browser is not provided by the active node@…`, run e2e with that node's bin on PATH** — it was installed globally under another mise Node, so `scripts/e2e.sh` only warns `agent-browser not found` and every flow fails. Fix: `PATH="$HOME/.local/share/mise/installs/node/<version>/bin:$PATH" ./scripts/e2e.sh` (the version is named in the error), or `npm i -g agent-browser` for the active Node. Evidence: `scripts/e2e.sh:51-52`. (2026-11-24)
- **Plan a Claude Code session restart before smoke-testing a newly added `.claude/agents/*.md`** — live loading is unreliable: 5 agents added 2026-11-26 into an existing folder showed up without a restart, but `implementer`/`test-writer`/`doc-writer` added 2026-11-27 into the same existing folder (valid YAML frontmatter) failed with `Agent type 'implementer' not found. Available agents: architecture-reviewer, …`, as did agents created together with the folder. Run the agent itself after the restart. Evidence: Agent tool errors for `client-reviewer.md` (2026-11-23), `researcher.md` (2026-11-26), `implementer.md` (2026-11-27). (2026-11-23, 2026-11-26, 2026-11-27)
- **Run depcruise for own code from the repo root with package-relative args: `server/node_modules/.bin/depcruise --config server/.dependency-cruiser.cjs --ignore-known .dependency-cruiser-known-violations.json src`** (same binary + `client/.dependency-cruiser.cjs` for the client) — tsconfig `paths` without `baseUrl` resolve against cwd, so from the root every `@devdigest/*` / `@/*` import was unresolved (53 server, 267 client); each config does `process.chdir(__dirname)`. The agents' read-only Bash hook blocks `cd`, hence this form. Evidence: `server/.dependency-cruiser.cjs`, `client/.dependency-cruiser.cjs`. (2026-11-26)
- **Preload `user-invocable: false` skills into a subagent via `skills:` in `.claude/agents/*.md` — it works** — `client-reviewer` started with `client-layout` (`user-invocable: false`) already in context and quoted `## 3. Component folder anatomy` without a Read. Only `disable-model-invocation: true` blocks preload. Evidence: smoke run of a `client-reviewer` agent with `skills: [client-layout]` on 2026-11-23 (agent file since removed; `pr-self-review` uses `general-purpose` + Read instead). (2026-11-23)
- **Don't guard subagents with PreToolUse hooks by default; scope them by instructions and add a hook only for a misbehaviour actually seen** — in the intent-layer run (2026-11-27) the agent guard hooks (`agent-readonly-bash.sh` allowlist, `agent-write-scope.sh`, `agent-spec-write.sh`) blocked no harmful action but cost many turns: writes into a worktree under `.claude/worktrees/` were refused, `grep`/`cd`/`git -C`/`sed` were blocked, `pnpm db:generate` and a `PATH=… ./scripts/e2e.sh` prefix were refused, and doc-writer could not touch stale `TESTING.md`/`specs/`. They were removed. If a hook is ever needed again, mind the platform facts: a subagent inherits the session's auto / `acceptEdits` / `bypassPermissions` mode (its `permissionMode` is ignored), a `disallowedTools` Bash specifier removes the whole tool, `permissions.deny` `Edit(...)` rules are global, and Bash-written files bypass Edit rules. Evidence: this session's blocked calls; https://code.claude.com/docs/en/sub-agents "Permission modes", "Frontmatter fields". (2026-11-27)
- **From the repo root, run reviewer-core tests as `npm --prefix reviewer-core test -- <path>`, never `npm --prefix reviewer-core exec vitest run`** — `npm exec` keeps the caller's cwd, so vitest ran from the root and reported `Test Files 2 failed (2)` / `no tests`, yet exited 0; the `test` script runs inside the prefix dir (14 passed). `pnpm -C <pkg> exec vitest run` does change cwd and works. Evidence: both commands run on 2026-11-27. (2026-11-27)
- **Save Playwright-MCP screenshots under `.playwright-mcp/` in the repo and delete the folder after** — the plugin refuses paths outside the repo root (`File access denied: … is outside allowed roots`), so the session scratchpad can't be used, and `.playwright-mcp/` is not in `.gitignore`. Evidence: `.gitignore:21-22` ignores `playwright-report/` and `test-results/` but not `.playwright-mcp/`; `browser_take_screenshot` error; `git check-ignore .playwright-mcp` → not ignored. (2026-11-20)

## Recurring Errors & Fixes
<!-- exact error text → cause → fix -->
- **Record the `pr-self-review` verdict and run `git push` in separate Bash calls** — the guard hook checks the verdict before the command starts, so `commit && verdict PASS && git push` in one call is refused as a whole (`local changes differ from the last reviewed state`) and not even the commit runs. Evidence: `.claude/skills/pr-self-review/scripts/guard-pr.sh` (PreToolUse); blocked chained call on 2026-11-24. (2026-11-24)
- **Put shell commands that only *mention* `git push` / `gh pr create|merge` (tests, echo, heredocs, grep) into a script file and run the file** — the `pr-self-review` guard hook greps the raw Bash command string and blocks it (exit 2) unless the change set has a current PASS verdict, even when the words sit inside `printf` or a heredoc. Evidence: `.claude/skills/pr-self-review/scripts/guard-pr.sh` regex; `PreToolUse:Bash hook error: … local changes were not reviewed` on a smoke-test command. (2026-11-23)
- **Never wrap `git push` / `gh pr create` in a skill script to dodge the guard hook — run them as plain Bash commands** — the hook only sees the Bash command string, so a script would skip it, and the auto-mode classifier refuses to write such a script (`[Undermining Oversight]`). `create-pr` therefore issues push/PR directly and lets the hook gate them. Evidence: denied Write of `.claude/skills/create-pr/scripts/publish.sh`. (2026-11-23)
- **Install `server/` and `client/` with pnpm 10 (what CI pins), never pnpm ≥11** — pnpm 12 fails with `ERR_PNPM_IGNORED_BUILDS … Ignored build scripts: esbuild@0.21.5`, leaves `node_modules` with only `.pnpm/` and no links, drops a placeholder `pnpm-workspace.yaml` (`allowBuilds: esbuild: set this to true or false`) and rewrites `pnpm-lock.yaml` without the `pnpm.overrides` from `package.json` (postcss/katex security pins). Fix: `npm i -g pnpm@10`, `git checkout -- pnpm-lock.yaml`, delete the generated `pnpm-workspace.yaml` and `node_modules`, reinstall. `pnpm approve-builds` from the repo root reports nothing — there is no root package. Evidence: `.github/workflows/e2e-web.yml:47`, `client.yml:37`, `server-unit.yml:47,79`, `server-integration.yml:43` (`pnpm/action-setup` `version: 10`); `git diff client/pnpm-lock.yaml` removed the `overrides:` block. (2026-11-20)
- **Run `docker compose up -d` (not `./scripts/dev.sh`) after changing the Postgres port in `docker-compose.yml`** — `dev.sh` reuses an existing `devdigest-postgres` in `created`/`exited` state via `docker start`, which keeps the old port binding, so it fails again with `Bind for 127.0.0.1:5432 failed: port is already allocated`; compose recreates the container (the `devdigest_pgdata` volume survives). Evidence: `scripts/dev.sh:56`; `docker inspect -f '{{json .HostConfig.PortBindings}}' devdigest-postgres`. (2026-11-19)
